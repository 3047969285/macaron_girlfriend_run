# 产品需求说明书：歌曲世界（地图随歌曲起伏）

## 1. 背景

9 个世界已经配了 6 首歌（世界 0–8 → 素颜、身骑白马、谁、静悄悄、5点20AM、Lost、Lost、身骑白马、素颜），关卡名和背景装饰也是歌的气质。但地图本身还是“按世界函数摆平台 + 均匀撒场景”，一首歌的起伏、节拍在地图上看不出来，同一首歌的两个世界也只是换了颜色。

## 2. 目标

把每个世界的地图做成“这首歌的形状”：

1. **起伏**：地图的疏密和高度跟着歌的响度曲线走。轻的段落空旷平缓，副歌密集高耸，最响的地方有一个高潮场景。
2. **节拍**：场景落在小节线上，一小节的长度由歌的速度决定（走一小节的路 ≈ 唱一小节的时间）。
3. **推进**：同一世界的 11 关依次走完这首歌（关 0 是前奏和第一段，关 10 是后半和尾声），所以每一关的形状都不一样。
4. **标志物**：每首歌有自己的糖果造型（心形、马蹄、问号、月牙、钟面、箭头），出现在糖果波场景里。

不做：改地面主路线、改背景音乐的播放位置、改敌人和机关、改歌曲文件。

## 3. 歌曲数据

每首歌一份：歌名、速度（每分钟拍数）、32 点响度曲线（0 = 最轻，1 = 最响，已按歌曲自身排序归一化）。数据由 `assets/audio` 里的原曲离线分析得到，写成代码常量。

| 歌 | 世界 | 速度 | 糖果造型 |
|---|---|---|---|
| 素颜 | 0、8 | 84.5 | 心形 |
| 身骑白马 | 1、7 | 130.5 | 马蹄 |
| 谁 | 2 | 143 | 问号 |
| 静悄悄 | 3 | 88 | 月牙 |
| 5点20AM | 4 | 125 | 钟面 |
| Lost | 5、6 | 136 | 箭头 |

## 4. 需求与验收标准

### W1 歌曲数据与映射
- 世界 → 歌的映射只有一份，音频播放和地图共用，歌名与 `AudioService.songTitleFor` 一致。
- 每首歌 32 个响度值都在 [0, 1]，最大值 ≥ 0.95，最小值 ≤ 0.1；速度在 60–180。
- 小节长度（格）= `clamp((1840 ÷ 速度).round(), 12, 24)`（一小节 4 拍，跑步速度约 7.7 格/秒）。

### W2 关卡在歌里的位置
- 第 l 关（0–10）覆盖歌曲的 `[l/10 × 0.5, l/10 × 0.5 + 0.5]` 这一半长度的窗口；关卡内横向进度 t（0–1）对应窗口内的位置，响度用 32 点曲线线性插值。
- 第 0 关起点 = 曲线第一个点，第 10 关终点 = 曲线最后一个点。

### W3 疏密和高度跟着响度
- 场景在关卡里的分布按响度加权（响度越高放得越密，最低也有基础权重）。
- 把 99 个普通关的所有场景按中心位置的响度分成“响”（> 0.5）和“轻”（≤ 0.5）：响的场景数 ≥ 轻的 1.25 倍。
- 场景种类有“响度分”（tower 1.0、ziggurat 0.9、cloudRoom 0.8、staircase 0.7、valley 0.5、skyBridge 0.4、hangingGarden 0.3、archipelago 0.3、coinWave 0.1）；全部场景的“中心响度”和“种类响度分”的相关系数 > 0.15。

### W4 小节线
- 场景的起点尽量落在小节线上（小节线 = 18 + k × 小节长度）：全部场景里至少 50% 的起点离最近的小节线 ≤ 2 格。

### W5 高潮
- 每个普通关（场景 ≥ 5 个）恰好有 1 个高潮场景（`climax == true`）：它是离全关响度最高点最近的场景；它的最高一块砖行 ≤ g − 9（k ≥ 9）。

### W6 歌的标志物
- 糖果波场景有 70% 的概率摆成这首歌的标志造型（`motif == true`），其余沿用波浪/弧线/之字形。
- 标志造型的糖果相对位置与该歌的模板一致（左右镜像算同一种），糖果数 ≤ 10。
- 九个世界里每个世界至少出现一次标志造型；六种造型两两不同。

### W7 不破坏已有约束
- 场景总数、种类多样性、相邻不重复、世界性格、关与关不重复、地面主路线、天空弹簧通道、全套通关脚本等现有测试全部继续通过（阈值如需调整，在测试里写明原因）。

## 5. 风险

- 响度加权会让场景挤在响的段落：保持场景之间至少隔 2 列，放不下时回退到相邻空隙（沿用现有第二轮重放）。
- 小节线吸附会让可放位置变少：先试小节线 ±2 列，放不下再用原来的搜索范围。
- 速度估算可能差一倍（半速/倍速）：只用来决定一小节多长，限制在 12–24 格内。
