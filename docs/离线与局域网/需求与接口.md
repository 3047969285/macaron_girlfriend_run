# 没有外网也能拿到最新网页版

## 背景

网页版放在 GitHub Pages（github.io），国内不开外网时经常打不开或很慢；现在的入口还有两个问题让它离线必挂：

- `index.html` 用 `flutter_bootstrap.js?load=<当前毫秒>` 加载入口脚本，每次地址都不同，缓存永远命不中。
- `flutter_bootstrap.js` 取不到 `.last_build_id` 时用 `Date.now()` 当版本键，主程序地址每次也不同。
- 没有注册任何 Service Worker，浏览器不会把游戏资源留在本地。

## 目标

1. **能离线玩**：在能联网（或连着电脑局域网）时打开过一次，之后没有任何网络也能打开并玩，包括音乐。
2. **有网就是最新**：只要能连上来源（github.io 或电脑的局域网地址），就加载最新版并更新本地缓存；连不上才用缓存。
3. **没有外网也能更新**：电脑上一条命令构建最新版并通过局域网 HTTPS 提供；手机首次安装并信任本机专用证书后，连同一个 Wi-Fi 打开，等待离线资源准备完成，之后即使断网也能玩。

## 需求

- **O1 稳定入口**：`index.html` 用固定地址 `flutter_bootstrap.js` 加载入口脚本，不再带时间戳。
- **O2 版本键兜底**：`flutter_bootstrap.js` 取 `.last_build_id` 成功后写入 `localStorage['macaron.build']`；失败时先用这个存档值，没有存档才用 `Date.now()`。
- **O3 Service Worker**：新增 `web/offline_sw.js`，由 `flutter_bootstrap.js` 在启动前注册（作用域为站点根，注册失败不影响启动）。策略：
  - 只处理同源 GET 请求。
  - 网络优先：请求 4 秒内成功就返回并把完整的 200 响应写入缓存（缓存键忽略查询串，即 `ignoreSearch`）；失败或超时就用缓存。
  - 带 `Range` 头的请求（音频）：缓存里有完整文件时，从缓存切出对应字节范围返回 206；没有就走网络。
  - 运行时缓存名 `macaron-offline-v1`；完整版本缓存在独立缓存中，全部资源写入成功并再次确认版本后才切换，失败时保留上一完整版本。激活时接管页面（`clients.claim`），安装时 `skipWaiting`。
- **O4 预热**：首帧出现后，如果在线、没开省流量、且本版本还没预热过（`localStorage['macaron.warm']` ≠ 版本键），页面在后台把 `assets/AssetManifest.json` 里列的所有资源和启动用到的核心文件（`main.dart.js`、`flutter.js`、`canvaskit/` 下的 wasm 和 js、`manifest.json`）各完整请求一次（经 Service Worker 写入缓存），必须从来源成功获取并逐个写入缓存，全部写入完成后才记下版本键并提示可以断网；失败时显示重试提示。
- **O5 不依赖外网**：`web/` 下的 html 和 js 里不出现除 `www.w3.org` 之外的 `http(s)://` 地址。
- **O6 局域网脚本**：新增可执行的 `scripts/serve_lan.sh`：默认构建网页版（参数 `--no-build` 跳过构建），再调用 `scripts/serve_lan.py` 在 8080 提供 HTTPS，打印局域网地址和证书安装说明。生成的证书和私钥保存在 Mac 用户目录，私钥不得放进网页目录或提交；手机需安装并信任专用 CA，地址变化时自动签发新服务证书。

## 验收

- `test/web_offline_test.dart` 静态检查 O1、O2、O3 的关键标记、O5、O6（文件存在且可执行、含关键命令）。
- 浏览器实测：用 `scripts/serve_lan.sh --no-build`（或等价的本地服务）打开页面，等 Service Worker 激活且预热完成后停掉服务，重新加载页面：游戏仍能进入首页并开始一关，音频文件能从缓存读取；再启动服务并重新加载：能取到新的构建标识。把证据（`navigator.serviceWorker`、`caches` 内容数量、截图结论）写进报告。
- 全套测试和 `dart analyze lib test` 通过。

## 不做

不改游戏逻辑；不引入新的打包依赖；不改 GitHub Pages 的部署方式。

## 安全与使用限制

首次使用局域网 HTTPS，需要在 iPhone 手动安装并信任 Mac 生成的专用 CA；只在自己控制的设备信任，CA 私钥不可分享。普通局域网 HTTP 不是安全上下文，不能提供 Service Worker 离线缓存。不同网址各自拥有独立缓存，局域网缓存不能自动转移到 GitHub Pages，反之亦然。iPhone 浏览器存储空间和回收策略可能清除缓存，须等页面提示准备完成后再离线。

## 接口文档

`scripts/serve_lan.sh [--no-build]` 在 8080 端口提供 HTTPS；`scripts/serve_lan.py --port` 可指定测试端口。离线资源按当前网址的来源隔离；首次加载需等待界面提示完成。

## 测试补充

除全量 Flutter 测试和静态分析外，检查证书链及私钥权限，并在浏览器验证缓存完成、停服后重新打开和音频读取。证书必须在目标 iPhone 手动安装信任后，才能验证手机局域网完整离线流程。

## 本机验收记录

在 Mac Safari 的本地安全上下文中，首次联网等待提示“离线资源准备完成”，停掉服务后可重开游戏并进入关卡；《素颜》《身骑白马》音频可在停服后读取。模拟新版本的一首歌曲下载失败后，页面提示未完成；停服后旧版首页和该歌曲仍可读取。局域网 HTTPS 证书链、私钥权限和本机局域网 IP 的 TLS 主机名验证通过。iPhone 需要先手动安装并信任证书，尚未进行目标手机实测。
